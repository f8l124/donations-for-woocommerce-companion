# v0.9.0 — Conversion UX

The conversion UX release. Per-preset impact labels turn abstract amounts into concrete outcomes; admins see a faithful donor-form preview as they configure templates and campaigns.

## Highlights

### Donor impact messaging

Per-preset impact labels — free-form text ("Provides school supplies for one student") translatable via WPML — render in the donor's language alongside each preset. Four display modes:

| Mode | Behavior |
|---|---|
| **Below preset** *(default)* | Full-width row beneath each preset button. Easiest to read; doesn't crowd the button. |
| **Inline** | Subtext within the preset button. Compact for tight layouts. |
| **Tooltip** | CSS tooltip on hover/focus + screen-reader-only `aria-describedby` for a11y. |
| **Card** | Each preset becomes a self-contained card. Best for high-engagement campaigns. |

Plus:
- **Featured presets** — mark one preset per interval; donors see a "Most popular" badge + subtle border accent. Single-featured-per-interval enforced server-side.
- **Per-interval subtitle** above the preset grid ("Become a monthly sponsor").
- **Annual equivalency** below the form with `{amount}` / `{annual_amount}` token substitution that updates live as the donor changes amounts.
- **Custom-amount impact label** alongside the donor's free-form amount input — useful when per-preset impact labels don't apply to arbitrary amounts.

### Live admin preview pane

`Donations Companion → Settings`, `→ Templates → Edit`, and the campaign edit screen now host a live preview pane. Debounced 350ms updates render the donor-facing form into an iframe via a REST endpoint. Same overlay JS that runs on donor pages also runs in the preview iframe — pixel-faithful results.

Toolbar:
- **Viewport** — Desktop / Tablet / Mobile (clamps iframe max-width)
- **Engine simulation** — Auto / WC Subscriptions / Subscriptions for WooCommerce / No engine. Verify how the form degrades across engine states without juggling test sites.
- **Language** *(only when WPML active)* — render the preview as if the donor's site were in any active WPML language.
- **Currency** *(only when WCML active)* — pass-through for Phase 6's per-currency presets (v1.0.0).

### Defense in depth on submit

Three independent layers prevent preview HTML from ever submitting a real donation:

1. Server-side `Submit_Guard` rejects any AJAX submit with `dfwc_preview` POST flag.
2. Overlay JS sees `data-preview="1"` on the wrapper, disables the submit button, shows a "Preview only" toast on click.
3. Preview iframe's mock submit button ships with the `disabled` attribute already set.

## Backward compatibility

Existing v0.8.x campaigns continue to render unchanged. Per-preset `impact_label` / `is_featured` / `sort_order` fields were already in storage from Phase 3; v0.9.0 wires them into the donor-side renderer. New per-interval fields (`subtitle`, `annual_equivalency`, `impact_display_mode`, `custom_amount_impact_label`) default to safe values and don't alter existing behavior until admins fill them in.

## WPML

Six new admin-defined string fields registered with WPML String Translation under stable namespaced keys:
- `<template_id>.<interval>.subtitle`
- `<template_id>.<interval>.annual_equivalency`
- `<template_id>.<interval>.custom_amount_impact_label`
- `<template_id>.<interval>.presets.<idx>.impact_label`
- Same set under `_campaign:<id>` for per-campaign overrides
- Same set under `_global` for global-defaults strings

The preview pane's simulate-language toggle calls `wpml_switch_language` server-side around the render so admins can verify translations without leaving the admin.

## Architecture

- `Validation\Template_Validator` — centralized config sanitizer used by REST. Reusable for future Templates_Page / Meta_Box deduplication in v0.10+.
- `Frontend\Preview_Renderer` — standalone, no DB lookups. Emits the same data-attribute payload as `Renderer::wrap_with_overlay` plus a mock-parent scope (`.wc-donation-in-action`, `.row1`, hidden inputs, disabled submit button).
- `REST\Preview_REST_Controller` — admin-only POST endpoint, `manage_woocommerce` gated, rate-limited to 10 req/sec/user, `Cache-Control: no-store`.

## Test coverage
