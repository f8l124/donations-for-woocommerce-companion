# v2.2.0 — Augment all campaigns by default

**The default flips.** Companion now augments every published `wc-donation` campaign with our donor form out of the box — no per-campaign opt-in required.

Up through v2.1.0, augmentation was gated on `Config_Resolver::is_configured()` per campaign — meaning only campaigns where the admin had saved a template assignment, per-campaign overrides, or legacy v0.6.x intervals meta got our form. Fresh installs and unconfigured campaigns rendered parent's vanilla form. This surprised admins who reasonably expected "install companion = get companion's form everywhere", and the gap was the actual reason most sites installed the plugin in the first place.

v2.2.0 ships an `augment_all_campaigns` global setting (default **on**) that makes augmentation universal. Admins who want the old behavior can flip it off in Settings → General.

## Why this is the right default

> install companion → get companion's form everywhere

Is the obvious mental model. Most admins:

- Don't realize companion has a per-campaign opt-in gate.
- Save templates / overrides only on the few campaigns they explicitly configure, leaving the rest on parent's vanilla form by accident.
- Don't notice the inconsistency until a donor reports it ("why does the donate page look different on this campaign?").

The historical gate had a real purpose: allow sites to incrementally adopt companion without disrupting existing campaigns. That use case is real but rare. The toggle preserves it for sites that need it.

## Implementation

`Defaults::for_global()` adds:

```php
'augment_all_campaigns' => true,  // Phase 18 (v2.2.0)
```

`Frontend\Context_Augmenter::should_augment( $campaign_id, $context )` (new public static helper) encapsulates the gating decision:

```php
$global             = Config_Resolver::get_global_settings();
$augment_all        = ! empty( $global['augment_all_campaigns'] );
$default_should_aug = $augment_all ? true : Config_Resolver::is_configured( $campaign_id );

return (bool) apply_filters(
    'dfwc_should_augment_parent_form',
    $default_should_aug,
    $campaign_id,
    $context
);
```

When `augment_all_campaigns` is on (the default), `is_configured` is bypassed entirely. When off, behavior matches v0.7.0 — v2.1.0 exactly.

The `dfwc_should_augment_parent_form` filter remains the per-campaign escape hatch in both modes:

```php
add_filter( 'dfwc_should_augment_parent_form', function ( $should, $campaign_id ) {
    if ( $campaign_id === 1234 ) {
        return false; // legacy campaign — keep parent's vanilla form
    }
    return $should;
}, 10, 2 );
```

## Settings UI

*WooCommerce → Donations Companion → Settings → General* now includes:

- **Augment all campaigns by default** (checkbox, default on)
  - "Apply our donor form to every campaign automatically."
  - Description explains the legacy behavior + filter escape hatch.

## Test coverage

245 → 250 cases, 629 → 636 assertions.

New `Context_Augmenter_Test` (5 cases) locks both branches of the gating decision:

- `augment_all_campaigns=true` + unconfigured campaign → augments
- `augment_all_campaigns=false` + unconfigured campaign → does NOT augment
- `augment_all_campaigns=false` + configured campaign → augments
- Filter forces off even when augment-all is on (legacy campaign carve-out)
- Filter forces on even when augment-all is off and campaign is unconfigured

`Defaults_Test` extended to verify the new key + default value.

## Backward compat

- Sites where the old per-campaign-opt-in behavior is desired (rare) can flip the toggle off in one click.
- The `dfwc_should_augment_parent_form` filter continues to work identically — listeners written against v2.1.x continue to receive the same arguments and have the same override authority.
- No data migration required. The new option key gets created on first read with the default value `true`.
- Sites that had every campaign configured on v2.1.x see no behavior change (already augmented).
- Sites with mixed configured/unconfigured campaigns now get all of them augmented (the change). Use the filter to carve out specific campaigns if any need to stay vanilla.

## Why this is a minor bump (not major)

The default behavior changes. Per `docs/release-process.md`:

> Major: removal of a documented feature OR new architectural surface.

This is neither — it's a sensible-default flip with a one-click revert. Hook contract unchanged. Data unchanged. APIs unchanged. The architectural change happened in v2.1.0 (QBO extraction); this is a behavior tweak on top.

## Upgrade story

For most sites: install v2.2.0 → all campaigns now show the companion form.

For sites that explicitly want some campaigns on parent's vanilla form:

- Option A: add a `dfwc_should_augment_parent_form` filter that returns false for those specific campaign IDs.
- Option B: flip the global toggle off (Settings → General) and rely on the v0.7.0 — v2.1.0 per-campaign-opt-in semantics.

Either works. Option A is more targeted (doesn't change the rest of your site's behavior); Option B is the full revert.
