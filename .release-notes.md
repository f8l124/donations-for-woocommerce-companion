# v2.5.0 — Per-cause progress bars

Visible reward for the v2.4.0 cause-aware investment. When admins configure per-cause goals on a campaign, donors now see inline progress bars next to each cause in parent's picker — "$3,200 of $5,000 · 64% to goal" — so they can choose under-funded causes if they want.

This is a small, contained, donor-facing polish release. Cleanest cap on the cause-aware-giving feature set before pivoting to GiveSpring.

## What ships

### Donor side

- **Inline progress bar** under each cause in parent's `.causes-dropdown` picker.
- **Label below the bar:** `"$X of $Y · N% to goal"` for open causes, `"Goal met!"` for closed.
- **Color cue:** green gradient bar for open causes, yellow gradient for closed (matches the v2.4.0 closure-prompt color vocabulary).
- **Locale-aware currency formatting** via `Intl.NumberFormat`. Uses `dfwcCompanion.locale` + `dfwcCompanion.currencySymbol` localize values.
- **ARIA-compliant** (`role="progressbar"`, `aria-valuenow`, `aria-valuemax`).
- **Smooth animation** — bar fills with a 0.4s ease transition on first render.

### Server side

- New static method: `Cause_Closure_Service::progress_for_campaign( int $campaign_id ): array`. Returns every cause with active tracking (`enabled = true` AND `goal_amount > 0`) with name + goal + raised + percent + closure flag. Reuses the v2.4.0 Cause_Raised_Aggregator's 3-layer cache (memo + transient + SQL).
- New wrapper data attribute: `data-cause-progress`. Empty `{}` on campaigns with no tracked causes.
- Percent is clamped server-side to 0-100 (overfunded causes show as full; closure UX handles overage messaging).

## Verification

```bash
composer check                   # PHPCS / PHPStan / PHPUnit all green
node scripts/check-version-consistency.js
```

Manual sandbox verification:

1. On a v2.4.0 campaign with per-cause goals configured (e.g., Education $5000, Healthcare $1000), seed some donations to bring Education to $3200 raised and Healthcare to $1000.
2. Reload the donor view of that campaign.
3. Verify each cause's `<li>` shows a progress bar:
   - Education: green bar at 64%, label "$3,200 of $5,000 · 64% to goal"
   - Healthcare: yellow bar at 100%, label "Goal met!"
4. Verify a campaign with NO per-cause goals shows the standard cause picker unchanged (no bars).

## Backward compat

Zero behavior change on:
- Sites without v2.4.0 cause goals enabled
- Campaigns where admin hasn't configured per-cause goals (the data-cause-progress attribute ships `{}`, JS bails immediately)
- Sites running prior companion versions before upgrade

No data migration. No new options. No new admin UI surface.

## Architectural note

v2.5.0 closes the v2.4.0 polish loop. The cause-aware-giving feature set is now feature-complete for v2.x:
- v2.4.0: per-cause goals + 3 closure modes + Submit_Guard enforcement
- v2.5.0: per-cause progress visualization

Future cause-aware refinements (refund-aware aggregation, cross-currency goals, recurring crypto) are deferred to v2.6+ if user demand surfaces. The next major work shifts to **GiveSpring v0.1** as a separate fork repo (see `plans/givespring/spec.md`), keeping companion stable for parent-augmenter use cases.
