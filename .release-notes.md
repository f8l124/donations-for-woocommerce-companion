# v2.2.1 — Campaign image defaults to off

Sensible-default tweak. The companion overlay is the donor's primary visual focus; on most themes, parent's campaign-image hero block above the form doubles up the visual weight without adding information. v2.2.1 flips the default to **hide the campaign image** in the donor view.

Existing campaigns with stored display overrides keep their saved value — the layered config architecture guarantees stored values always win over defaults.

## Layered config — what wins for `display.show_image`

```
Defaults              show_image = false  (NEW in v2.2.1)
   ↓
Global option         (display block in dfwc_companion_global_settings; usually unset)
   ↓
Template config       (when campaign assigned a template)
   ↓
Per-campaign meta     _dfwc_companion_overrides.display.show_image  ← always wins
```

A campaign with no display overrides and no template assignment falls all the way through to the default → image hidden.

A campaign with **any** of the following keeps showing the image:

- Explicit `_dfwc_companion_overrides.display.show_image = true` saved via the meta box.
- Assigned template that sets `display.show_image = true` in its config.
- Filter override via `dfwc_companion_resolved_config` returning `true`.

In practice: every campaign you've ever opened in the meta box and saved has stored display overrides. The new default only affects campaigns you've never touched + brand new campaigns going forward.

## Per-campaign override seam

If a specific campaign needs the image visible:

1. **WP admin → edit the campaign → Companion meta box → Display Options → "Show campaign image" → check → Update**.

That stores `_dfwc_companion_overrides.display.show_image = true` and the image renders for that campaign regardless of the default.

## Why this is the right default

- Donors visually anchor on the donate form, not the campaign hero. Two visual focal points compete for attention; one converts better.
- Parent's image block is variable quality across themes; on Elementor / FSE / block themes it often crops or stretches awkwardly above an interactive donor form.
- Admins who want the image still get it with one checkbox click in the meta box.
- The historical default was inherited from parent's behavior, not chosen by us. v2.2.1 is when we own the default.

## Files changed

- `includes/Config/Defaults.php` — `show_image` default flipped from `true` to `false` in `for_campaign()['display']`.
- `assets/js/dfwc-overlay.js` — donor-side safety fallback flipped to match (when the wrapper's `data-display` JSON parse fails, default to `show_image=false` instead of `true`).
- `tests/unit/Defaults_Test.php` — new test pinning the new default; existing test updated.
- `tests/unit/Config_Resolver_Test.php` — `test_resolve_display_returns_defaults_when_unset` updated to assert the new default.

## Backward compat

Stored overrides win. Existing campaigns with `show_image=true` in `_dfwc_companion_overrides` continue rendering the image. No data migration. No API change. No filter contract change. Patch-version bump (v2.2.0 → v2.2.1).
