# v2.1.0 — QBO Sync extracted to sibling plugin

QuickBooks Online sync extracted from this companion into a new sibling plugin: **[Donations for WooCommerce QuickBooks Sync](https://github.com/f8l124/donations-for-woocommerce-qbo-sync)** v1.0.0. The companion's job is donor-form UX + emitting Phase 9 event hooks; anything that *consumes* those hooks (this, future FluentCRM / GA4 / Xero / Slack connectors) belongs in a sibling plugin. Bundling them blurred concerns the codebase wants to keep separate.

Migration is automatic for existing v2.0.x sites — the sibling plugin reads the same option keys + uses the same Action Scheduler action slug + same `AUTH_KEY`-derived encryption, so tokens / mappings / sync log all carry over with **no reconnection required**.

## Architectural framing

```
┌───────────────────────────────────────┐
│ Donations for WooCommerce Companion   │
│  • Donor form (overlay, blocks)       │
│  • Templates / config layers          │
│  • Phase 9 event hooks (the API)      │
│  • Stock pledges / Overflow webhook   │
└────────────────┬──────────────────────┘
                 │ dfwc_companion_donation_submitted
                 ↓ (and other Phase 9 hooks)
   ┌─────────────────────────┐  ┌─────────────────────────┐
   │ QBO Sync (new sibling)  │  │ Future: FluentCRM, GA4, │
   │ v1.0.0                  │  │ Xero, Slack, Mailchimp  │
   └─────────────────────────┘  └─────────────────────────┘
```

The Phase 9 event hooks are exactly the right architectural seam. v2.0.0 buried QBO sync inside the companion bundle because shipping fast was the priority; v2.1.0 separates concerns now that the pattern is clearer.

## What's added to companion

- `includes/Admin/QBO_Migration_Notice.php` — one-time admin notice. Surfaces ONLY when the companion-era `dfwc_qbo_oauth_tokens` option exists AND the sibling plugin isn't loaded. Tells the admin to install the sibling. Dismissible. Auto-hides once the sibling plugin is detected.

That's the only addition. Everything else is removal.

## Migration story for existing v2.0.x sites

Drop-in. Two activation orders both work:

**Order A: Install sibling first, then upgrade companion**
1. Install + activate `donations-for-woocommerce-qbo-sync` v1.0.0.
2. Sibling's `Migration_Detector` runs on `Plugin::boot()`, copies `qbo_*` settings out of `dfwc_companion_global_settings` into its own option, logs a "Migrated" entry to the sync log, marks the migration done.
3. Upgrade companion v2.0.x → v2.1.0 (which removes the duplicate QBO code from companion).
4. Sync continues uninterrupted.

**Order B: Upgrade companion first, install sibling after**
1. Upgrade companion v2.0.x → v2.1.0.
2. QBO sync stops syncing (companion's listener no longer registered) — but tokens/mappings/log persist in DB untouched.
3. Companion's new `QBO_Migration_Notice` admin notice surfaces with a download link to the sibling.
4. Install + activate sibling.
5. Sibling's `Migration_Detector` runs, sync resumes from where it left off.

Either way: zero reconnection, zero data loss.

Sites that didn't use QBO on v2.0.x see no functional change at all.

## Hook contract — unchanged

The companion's Phase 9 hook signatures + firing semantics are identical:

```php
do_action(
    'dfwc_companion_donation_submitted',
    $campaign_id,    // int
    $interval,       // 'one_time' | 'monthly' | 'annual' | 'weekly' | 'quarterly' | 'semiannual' | 'custom'
    $amount,         // float
    $context,        // 'single' | 'shortcode' | 'widget' | 'checkout' | 'cart' | 'cart_block' | 'preview' | 'stock' | ...
    $currency,       // ISO 4217 (uppercased)
    $language,       // locale code; '' if WPML inactive
    $reason          // empty for success
);
```

Existing listeners (FluentCRM contact tagging, GA4 sender, custom webhooks, future v1.4.0 crypto path, the new sibling QBO plugin) all consume the same contract. No code changes needed in any consumer.

The `dfwc_companion_qbo_payload` filter (legacy, from companion v2.0.x) is also still applied by qbo-sync v1.0.0 alongside its new `dfwc_qbo_sync_payload` filter — listeners written for the old filter name continue to work.

## Diagnostics extensibility

Companion's `dfwc_companion_contracts` filter is the documented extension seam for plugins to inject health checks into the Diagnostics page. qbo-sync v1.0.0 uses it; future connectors can do the same:

```php
add_filter( 'dfwc_companion_contracts', function ( $contracts ) {
    $contracts[] = new \DFWC\Companion\Contracts\Parent_Form_Contract(
        'my_check_id',
        'My Check Label',
        'Description shown in admin.',
        \DFWC\Companion\Contracts\Parent_Form_Contract::SEVERITY_WARNING,
        'my_check_callback'
    );
    return $contracts;
}, 10, 1 );
```

## Versioning rationale

This is technically a feature removal from companion (per `docs/release-process.md`, removal of a documented feature is a major-bump trigger). However, the functionality *moves* to a sibling rather than going away. Calling this v3.0.0 would overstate the impact for sites that don't use QBO. v2.1.0 (minor) reflects:

- Hook contract: unchanged.
- Donor flow: unchanged.
- Most code: unchanged.
- Admin surface for non-QBO users: unchanged.
- Admin surface for QBO users: re-mounted under the sibling plugin's submenu.

Sites that use QBO MUST install the sibling plugin to keep syncing. The migration notice surfaces this loudly.

## What's NOT changing

- Donor-form behavior.
- Stock donations / Overflow webhook (Phase 14A; bundled here as before).
- Goal-aware giving (Phase 13; bundled here as before).
- Phase 9 event hooks contract.
- All configuration UI for non-QBO features.
- All public filters / actions.
