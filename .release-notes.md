# v1.0.0 — First Stable Release

The companion graduates to v1.0.0. This release bundles the v0.9.0 → v1.0.0 changes — per-currency presets, advanced cadences, the `wp dfwc-companion health` CLI, opt-in uninstall, and the v1.0.0 documentation suite — and marks the plugin as ready for production nonprofit use.

## Headline features

### Per-currency preset amounts (Phase 6)

A nonprofit running a "$25/month for school supplies" campaign in the US wants a "£20/month" or "€22/month" equivalent shown to UK or EU donors — not the auto-converted "£19.78/month" that WCML produces, which kills conversion. Phase 6 lets admins define per-currency preset amounts that resolve at render time based on the donor's active currency.

| | Behavior |
|---|---|
| **Storage** | Sparse `currency_overrides` map per interval block. Only fields that differ from the base block need to be present (override `amount` only; labels / impact_label / featured / sort_order inherit). |
| **Active-currency lookup** | WCML primary (`wcml_get_user_currency()`) → WC base fallback. The `dfwc_companion_active_currency` filter is the final say so non-WCML stacks (WCPay Multi-Currency, Aelia Currency Switcher) can wire in via a 5-line snippet. |
| **Supported set** | `wcml_multi_currency()->get_active_currencies()` when WCML is on; just base currency otherwise. Filterable via `dfwc_companion_supported_currencies`. |
| **Donor-side resolution** | `Frontend\Renderer::build_form_config` lazily resolves each interval block per the donor's active currency — `Config_Resolver` itself stays cache-friendly and currency-agnostic. |
| **Defense** | `Submit_Guard` re-resolves the block under the active currency before validating amount min/max, so a £5 donation in GBP isn't rejected against the base USD threshold. |
| **Admin UX** | Per-interval "Per-currency preset amounts" section in both the campaign meta box and Templates page edit form. One collapsible `<details>` per non-base supported currency with a sparse table (amount-only inputs); empty rows fall back to base. UI hidden entirely on monolingual / single-currency sites. |

### Advanced giving intervals (Phase 7)

Some nonprofit giving models don't fit One-time / Monthly / Annually. Weekly tithing, quarterly mission support, semi-annual memberships, "every 6 weeks" sponsorship cycles — these are real, but adding them to the default UX clutters the form for the 95% case.

Phase 7 introduces them as **opt-in** intervals admins enable globally via *Settings → Advanced giving intervals* and assign per template / per campaign. Default install behavior (only One-time / Monthly / Annually visible) remains the v0.6.x experience.

| Interval | Cadence |
|---|---|
| **Weekly** | every week |
| **Quarterly** | every 3 months |
| **Semi-annually** | every 6 months |
| **Custom** | admin-defined `every N {day/week/month/year}` plus a translatable donor-facing label ("every 6 weeks") |

Custom interval gets a `{custom_label}` token usable in the CTA template — so admins can configure cadence + copy independently. `Engine_Interval_Map` is the single source of truth for the interval → engine cadence translation; both WCS and WPS SFW key sets ship in every recurring submit. Server-side `Submit_Guard` validates each posted `(period, multiplier)` tuple against the campaign's enabled intervals, including the admin's custom cadence — so even a determined attacker scraping the donor form can't manufacture a cadence the admin didn't authorize.

When ≥5 intervals are enabled on a campaign, the donor-side overlay automatically rolls everything past the first three into a **"More options ▾"** dropdown; ≤4 enabled stays inline.

## Operations

### `wp dfwc-companion health`

Runs the same diagnostic checks the Diagnostics admin page exposes, formatted for the terminal or for piping into a monitoring agent. JSON / table / markdown output.

### Opt-in uninstall

`uninstall.php` respects the admin's `preserve_data_on_uninstall` preference (default: on). Opt-in deletion cleanly wipes companion options, post meta on `wc-donation` posts, and `dfwc_`-prefixed transients via `$wpdb->prepare`. Never touches campaign posts, orders, or non-companion data — so a re-installed companion finds the parent's data intact.

## Backward compatibility

- Existing v0.9.x campaigns render unchanged. The new `currency_overrides` field defaults to empty per interval; the four advanced-interval slots default to disabled. Upgrading users see no UI change until they opt in.
- Storage round-trips advanced-interval data even when the global toggle is off, so admins can pre-configure intervals before flipping the toggle.
- Existing v0.6.x meta key fallback (`_dfwc_companion_intervals`) continues to be honored by `Config_Resolver` for sites that haven't yet saved a campaign under v0.7+.
