# v2.0.1 — Donor-flow Hotfix

**Critical fix.** Donor-side AJAX submit was throwing `ArgumentCountError` and stalling on an infinite spinner on every site running **v1.1.0 — v2.0.0**. Any donor reaching the submit step on those versions saw their request 500-out, the loader spin forever, and no donation get processed.

Upgrade required for any v1.1.0 — v2.0.0 site that ever takes a donation.

## Root cause

`Analytics\Submission_Tracker` (shipped in v1.1.0 with Phase 9 event hooks) registered parent's `wc_donation_alter_donate_response` filter with `accepted_args=2` and a callback signature `on_donate_response($response, $request)`.

Reading parent's source at `class-wcdonationorder.php` confirms the filter is dispatched at three sites:

```php
// Line 1592
echo json_encode( apply_filters( 'wc_donation_alter_donate_response', $response ) );
// Line 1634
echo ( json_encode( apply_filters( 'wc_donation_alter_donate_response', $response ) ) );
// Line 1821
echo ( json_encode( apply_filters( 'wc_donation_alter_donate_response', $response ) ) );
```

All three pass exactly ONE argument. Our callback required two. PHP's behavior:

```
WP_Hook::apply_filters() — 1 arg passed
    → call_user_func( $callback, $response )
    → ArgumentCountError: Too few arguments to function ... 1 passed and exactly 2 expected
    → AJAX 500 → donor sees infinite spinner; no donation processed
```

## Why this slipped through

- The unit test suite (552 → 691 assertions across v1.1.0 → v2.0.0) never exercised this filter end-to-end. It locked the privacy guard, the rate limit, the sanitizers — but not the integration with parent.
- Local Playwright e2e against wp-env didn't catch it either, suggesting the wp-env baseline behaves differently from production (possibly WP version, PHP error-mode, or parent-plugin version skew). Confirmed Hostinger/PHP 8.x setups surface the ArgumentCountError as a fatal mid-AJAX.
- The fix landed in the same hour the bug surfaced: production debug log showed the trace at 2026-04-30T02:28:43Z; root cause + patch was straightforward once seen.

## Fix

`Analytics\Submission_Tracker.php` lines 35–55:

- Bind with `accepted_args=1`.
- Callback signature now `on_donate_response($response)` only.
- Read the request payload from `$_POST` inside the callback. Safe because we're invoked mid-AJAX inside parent's `donation_to_order` action; `$_POST` is the donor's submission. Privacy posture unchanged — every field still flows through `Privacy_Guard` allow-list sanitizers and `absint`/float casts before reaching the `do_action` call.

## Regression test

New `tests/unit/Submission_Tracker_Test.php` (4 cases). The first case is the load-bearing one:

```php
public function test_callback_works_when_invoked_with_one_arg(): void {
    new Submission_Tracker();

    $_POST = array(
        'campaign_id' => '42',
        'amount'      => '25.00',
        'is_recurring' => 'no',
    );

    $captured = array();
    add_action(
        'dfwc_companion_donation_submitted',
        static function ( $campaign_id, $interval, $amount, $context, $currency, $language, $reason ) use ( &$captured ) {
            $captured = compact( 'campaign_id', 'interval', 'amount' );
        },
        10,
        7
    );

    $response = array( 'response' => 'success', 'message' => 'OK' );

    // CRITICAL: only one arg. If the binding is wrong (accepted_args=2,
    // signature requires 2), PHP throws ArgumentCountError here.
    $out = apply_filters( 'wc_donation_alter_donate_response', $response );

    $this->assertSame( $response, $out );
    $this->assertSame( 42, $captured['campaign_id'] );
    $this->assertSame( 25.0, $captured['amount'] );
}
```

This test would have failed against v1.1.0 — v2.0.0's binding. It locks v2.0.1's behavior so a future "let's pass the request as the second arg!" refactor can't silently bring the regression back.

## Upgrading

The v2.0.1 zip is fully backward-compatible — no settings change, no DB migration. Drop-in replacement:

1. WP-Admin → Plugins → upload `donations-for-woocommerce-companion-2.0.1.zip` → "Replace current with uploaded".
2. Test a $1 donation through your normal donor flow. Submit should complete instead of spinning.

For sites that adopted v1.2.0+ features (goal-aware giving, stock donations, QBO sync) those continue to work unchanged — this fix only touches the analytics hook bridge, not any of the feature surfaces shipped between v1.1.0 and v2.0.0.
